# Refactor Mission Proposals

Load only after related Missions are accepted and integrated into the current canonical source, and
only with user authority to investigate a separate structural Outcome. Current candidate correction
stays `revise`; a failed owner/boundary/oracle stays `replan`.

Bind exact reachable base/head/source ref, current owners and real consumers, accepted evidence, and
one demonstrated structural cause: duplicate authority, split behavior, repeated protective patches,
parallel production paths, consumerless capability, drift, or repeated rework/communication pressure.
Static links, churn, file/line/Mission count, scores, or aesthetics alone are insufficient.

Apply the necessity test: if deletion leaves clean success, known-defect prevention, and unique
owner/consumer edges unchanged, remove the mechanism instead of preserving or summarizing it. Prefer
owner convergence and deletion over adapters or compatibility paths.

A proposal names the preserved consumer behavior, no-change cost, quantitative structural target,
bounded independent Outcome, Origin, evidence/limits, acceptance, and non-goals. It requires fresh
planning and user-approved task dispatch; it inherits no candidate, Plan, Stop, or effect authority.
