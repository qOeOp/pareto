# Repair Test-Suite Corrosion with Test GC

## Activation

Load only when a current decision concerns test or glue redundancy, obsolescence, reachability,
mis-layering, replacement, or deletion, and the affected behavior can remain frozen. A low count,
coverage percentage, old file, slow test, helper signal, or desire for cleanup does not activate it.

## Evidence

Bind each candidate to current intent and contract authority, the real production consumer, selection
path, executable configuration, unique failure value, runtime and maintenance cost, and replacement
evidence. Use coverage, static reachability, import analysis, execution history, duplication signals,
and timing only as leads. Preserve unknown dynamic loading, unsupported languages, stale coverage,
and unobserved configurations as unresolved.

## Taxonomy

- **dead:** no authoritative configuration or consumer reaches the test or glue;
- **redundant:** another maintained oracle proves the same failure with no lost boundary value;
- **obsolete:** the test asserts a superseded contract or removed consumer;
- **implementation-coupled:** private calls, ordering, snapshots, or transforms replace behavior proof;
- **mis-layered:** a deterministic rule is tested above its narrowest stable owner;
- **distorted:** a mock, fake, environment, time, or concurrency model hides the real boundary;
- **expensive without unique value:** runtime or maintenance cost is observed but no distinct failure
  remains after replacement.

## Decision

Choose exactly one action per candidate: `keep`, `strengthen`, `replace`, `lower_layer`,
`delete_candidate`, or `further_investigation`. Select `delete_candidate` only after authority,
reachability, unique value, and replacement are closed. Keep localized repair in the current Mission;
route a separate refactor only through its existing integrated-evidence, proposal, consent, and
dispatch contract.

## Repair

Strengthen or add the replacement before removing obsolete evidence. Move deterministic rules to the
narrowest owner while retaining an affected boundary check when it has distinct value. Delete only
the exact admitted candidates and their now-unconsumed support code. Preserve every required behavior
and direct consumer; stop at a proposal when deletion safety remains incomplete.

## Anti-pattern

Never delete autonomously from coverage, reachability, helper output, age, runtime, test count,
mutation score, or an unexecuted test. Do not add one test per escaped bug, preserve implementation
mirrors as change detectors, or merge distinct boundary failures to reduce file count. Do not make
Test GC a fixed Mission cost or create a cleanup campaign from incidental evidence.

## Verification

Run the original failing or distinguishing scenario, every replacement oracle, the affected owner and
direct-consumer tests, and the real executable configuration. Prove the removed test or glue has no
remaining selection path or unique failure value. Compare relevant runtime when cost motivated the
decision. Inspect the complete diff for lost behavior and unconsumed support code, then run the final
root gate. Report unresolved dynamic reachability rather than inferring deletion safety.
