# Repair Skill Corrosion

## Activation

Load only when immutable Origin/candidate or real-Mission evidence shows wrong triggering, duplicate
authority, an invalid or cyclic load route, context inflation, a dead resource, weakened effects, or
another behavior regression in the Skill. File size, age, wording preference, or a hypothetical prompt
alone does not activate it.

## Evidence

Freeze the exact Skill Origin and candidate. Inspect frontmatter trigger ownership, the thin kernel,
conditional load predicates, resource links, direct consumers, scripts/assets, UI metadata, and real
Mission traces that expose the consequence. Parse the complete reference graph and retain byte/line
cost by actual route. Treat static prose review as supporting evidence; the candidate cannot certify
its own instruction or judge behavior.

## Taxonomy

- **trigger corrosion:** frontmatter is ambiguous, over-broad, or contradicted by another trigger owner;
- **authority drift:** lifecycle, effects, acceptance, or repair semantics have more than one owner;
- **load inflation:** ordinary or unrelated paths load conditional material with no decision consumer;
- **cycle:** references create a reverse edge or no-information-gain loop;
- **orphan:** a resource, script, asset, or metadata field has no real consumer;
- **kernel creep:** domain procedure, repair manual, report schema, or tool catalog enters the kernel;
- **effect regression:** instructions weaken approval, exact-candidate, fail-close, or live-effect bounds.

## Decision

Prefer no change, deletion, direct owner reuse, or moving detail behind an exact predicate. Keep one
frontmatter trigger owner and one lifecycle kernel. Materialize a leaf only with an independent loading
predicate, real consumer, and verifiable boundary. Update UI metadata only when it no longer matches
the Skill; do not use it as behavioral authority.

## Repair

Keep activation, five stages, main-agent authority, current-state-only, DAG invariants, progressive
routes, and safety in the kernel. Move domain methods to their existing owner; delete copied or
superseded authority in the same slice. Make each route state its exact predicate and Stop. Keep stable
output shapes in assets and deterministic code with real consumers in scripts. Add no state, registry,
scheduler, loader, compatibility shim, or unsupported host capability.

## Anti-pattern

Do not test prompt wording, add self-referential policy tests, hard-code a full-load bundle, copy QA
or lifecycle semantics into every leaf, or claim runtime behavior from a static link. Do not add
`hooks`, `evals`, `memory`, `sub-skills`, a second CLI, or a model table without observed platform and
consumer authority. Do not optimize net lines or token counts by deleting required evidence.

## Verification

Run the Skill validator, resolve every local resource link, and prove the reference graph has no new
cycle or duplicate authority. Exercise ordinary Missions and each changed trigger with real consumer
prompts; record the exact files and bytes loaded. Compare Origin/candidate behavior and effect bounds,
run affected helper calls and the repository root gate, and require a fresh independent instruction/
judge audit on the frozen candidate. Treat unavailable runtime observations as unavailable.
